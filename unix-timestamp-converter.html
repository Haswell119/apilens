Seconds or milliseconds — how to tell them apart

TimestampUnitDate it represents
1767225600seconds (10 digits)2026–01–01 — the usual Unix time
1767225600000milliseconds (13 digits)The same instant — what JavaScript's Date.now() returns

Rule of thumb: 10 digits is seconds, 13 is milliseconds, and 16 is microseconds (some tracing systems). Values before 1970 are negative and represent dates before the epoch. A “timestamp” in an API that decodes to a year around 55 000 is almost certainly milliseconds read as seconds.

Frequently asked questions

Is epoch time always UTC?

The Unix timestamp itself has no timezone — it counts seconds since 1970-01-01T00:00:00Z. This tool displays that instant in UTC and in your browser's local timezone so you can see both interpretations of the same number.

Why does my timestamp show a different year than expected?

Almost always a unit mismatch. A 13-digit value has been read as seconds and lands thousands of years in the future, or a 10-digit value read as milliseconds collapses into 1970. Switch the unit selector and it will line up.

What is the Year 2038 problem?

Signed 32-bit integers overflow on 2038-01-19T03:14:07Z. Anything still storing Unix seconds in a 32-bit signed field must be widened before then — which is why storing milliseconds in a 64-bit type is now the common default.

Does it handle macOS/Windows file times?

No. Those use different epochs (2001-01-01 and 1601-01-01 respectively). This converter handles the Unix epoch only — but you can add the offset in seconds to convert between them by hand.

Can I use it for JWT exp and iat claims?

Yes — those are Unix seconds. For a full view of a token, including human-readable expiry, use the JWT decoder.

Are the values I type stored anywhere?

No. All conversion is local JavaScript, there is no request and no analytics, so nothing you paste here leaves the browser.
