Frequently asked questions

Is this XML to JSON conversion done locally?

Yes. The XML is parsed with your browser's own DOMParser and converted in JavaScript. No request is made, so XML containing credentials, tokens or customer data never leaves the machine.

How are XML attributes handled?

Attributes are emitted as keys prefixed with @ (@id, @lang) so they can never collide with a child element of the same name. That is the same convention used by the common Java and Python XML-to-JSON libraries.

What happens to repeated elements?

If the same tag appears more than once under the same parent, the values are collected into an array. A single occurrence stays a plain value, which matches what most APIs expect.

Why are my numbers quoted in the JSON output?

Because XML does not distinguish 9.99 from "9.99". Quote-preserving output is lossless; if you need typed values, run the result through a schema-aware mapper.

Does it handle CDATA and comments?

CDATA sections are treated as text content and preserved in the value. Comments and processing instructions are ignored, since they carry no data.

What about invalid XML?

The tool reports the parse error instead of guessing. Validating and formatting the document first with the XML formatter usually shows you the unclosed tag immediately.
