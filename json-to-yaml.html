Frequently asked questions

Is the JSON to YAML conversion private?

Completely. Serialisation happens in JavaScript in this tab. There is no server call, no analytics and no logging — which matters for Kubernetes manifests, CI configs and anything holding a token.

Is the output valid YAML 1.2?

Yes. Indentation is consistent, keys are quoted when they contain characters that would change their meaning, and strings that YAML would otherwise coerce to numbers or booleans are single-quoted.

Can I use it for Kubernetes or CI configuration?

That is the most common use. Paste the JSON you got from kubectl get -o json or an API response and you get a manifest-shaped YAML scaffold to edit. Generated manifests should always be reviewed before you apply them.

Why are some strings wrapped in quotes in the output?

Because YAML is not JSON: yes, no, on, off, null and numeric-looking strings have special meanings. Quoting them preserves the exact value you had in JSON.

Does it convert YAML back to JSON?

This page is one-way (JSON → YAML). For structure comparison the JSON diff and JSON validator are the more useful neighbours.
